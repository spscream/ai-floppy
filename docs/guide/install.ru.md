# Установка и init

## Требования

- **Claude Code или Cursor.** floppy — плагин. Это не отдельная программа.
- **`bash`, `git` и git-репозиторий.** Каждая команда находит свои пути от корня
  репозитория. Вне репозитория каждая команда останавливается с ошибкой. Она не
  угадывает.
- **macOS или Linux.** CI гоняет тесты на обеих системах. Джоб macOS использует
  `/bin/bash` версии 3.2.57. Все скрипты обязаны работать с этой версией.
- **Больше ничего.** Скриптам не нужна ни одна другая программа. Сеть они
  используют только для команд `git`, которые вы можете прочитать в исходниках.

Для Windows используйте WSL. WSL для этих скриптов — линуксовый shell. Ни один
тест не использует нативный Windows-shell.

## Установка

### Claude Code

```
claude plugin marketplace add spscream/ai-floppy
claude plugin install floppy@floppy
```

То же самое можно сделать внутри сессии. Используйте `/plugin marketplace add
spscream/ai-floppy`, затем `/plugin install floppy@floppy`.

Имя `floppy` встречается во второй команде дважды. Так называется маркетплейс.
Плагин внутри маркетплейса называется так же.

### Cursor, из репозитория

1. Откройте Dashboard → Plugins → Add Marketplace → Import from Repo.
2. Введите `spscream/ai-floppy`.
3. Откройте Customize в боковой панели.
4. Найдите `floppy` и установите его.

Cursor должен иметь доступ к репозиторию на чтение. Если репозиторий приватный,
войдите в Cursor под учётной записью, у которой такой доступ есть.

### Cursor, из локальной копии

Используйте этот способ во время разработки плагина. Он же годится, чтобы
попробовать плагин без маркетплейса.

```
mkdir -p ~/.cursor/plugins/local
ln -s /path/to/ai-floppy ~/.cursor/plugins/local/floppy
```

Затем запустите Cursor заново. Cursor читает `.cursor-plugin/plugin.json` и
каталог `skills/` из этого расположения.

Во время разработки можно также указать `AI_FLOPPY_HOME` на вашу локальную копию.

После установки подготовьте репозиторий скиллом `init`. См. ниже.

### Cursor и несколько проектов сразу

В Cursor может быть открыто несколько проектов. Скилл выполняет свои shell-команды
в одном из них. Проект скилл не выбирает.

Каждая процедура печатает репозиторий первой строкой вывода
(`repo: /path/to/it`). Читайте эту строку первой. Читайте её до того, как `wrap`
выполнит свой шаг `commit`, потому что этот шаг индексирует, коммитит и пушит
файлы.

## Две устаревшие копии, не дающие сообщения об ошибке

### 1. Кэш плагина

`claude plugin update` сравнивает номера версий. Если номер версии тот же,
команда не копирует ни одного файла. После чего сообщает «already at the latest
version».

Результат — установленная копия возрастом в несколько дней. Измерено 2026-08-25:
в кэшированной копии лежал пустой каталог `scripts/`.

Чтобы это исправить, сделайте одно из двух:

- Увеличьте номер версии в `.claude-plugin/plugin.json`.
- Удалите плагин и установите его заново.

`.floppy/run` отказывается работать с каталогом кэша, в котором нет ни одного
файла `scripts/*.sh`. Это даёт внятное сообщение вместо позднего «No such file or
directory».

### 2. Файл-прокладка в вашем репозитории

`.floppy/run` — копия файла из плагина. Это не ссылка. Обновление плагина её не
меняет. Git перемещает её вместе с вашим репозиторием.

Поэтому `.floppy/run` может быть старше плагина. На второй машине он может
оказаться и новее плагина.

С версии 0.14.0 это значит куда меньше. Файл делает одно: находит плагин и
передаёт ему вызов. Команды и ключи конфигурации лежат в плагине. Новая команда,
новый ключ или новое значение по умолчанию доезжают до вашего репозитория одним
только обновлением плагина. Копировать файл заново ради них не нужно.

Одно всё же путешествует в копии: поиск плагина. Если этот поиск изменится,
старая копия может не найти плагин, который на месте. Отказ при этом громкий. Он
говорит `floppy plugin not found` и называет команды установки.

При каждом вызове `.floppy/run` сравнивает себя с файлом в плагине. Если файлы
различаются, он печатает одну строку в stderr. В этой строке — команда `cp`,
исправляющая копию.

Исправление — это команда `cp`, а не команда floppy. Так сделано намеренно.
Файл-прокладка, достаточно старый, чтобы требовать исправления, не знает новых
команд.

**Осторожно:** плагин старше копии — теперь полная остановка, а не частичная.
У плагина до 0.14.0 нет диспетчера, поэтому против него не выполнится ни одна
команда. Сообщение говорит об этом и называет каталог плагина, который был
использован.

## `init`

Выполните `init` один раз в каждом репозитории.

`init` задаёт два вопроса:

1. Каталог памяти. По умолчанию `.agent-memory`.
2. Язык заметок памяти.

Затем `init` делает всё перечисленное:

- копирует файл-прокладку в `.floppy/run`. Это единственный файл, который плагин
  кладёт в ваш репозиторий.
- пишет `.floppy/config`.
- создаёт индекс памяти `<memory_dir>/MEMORY.md`.
- создаёт файл состояния `docs/statuses/NOW.md`.
- добавляет приватную область памяти в `.gitignore`. Этот путь становится
  симлинком в приватный репозиторий памяти, и репозиторий с кодом не должен его
  нести. Имя — `memory_private_dir`, чтобы совпадать с тем, что создаёт
  `workplace`.
- добавляет указатель на `agent-memory` в ваш `AGENTS.md`.

`init` идемпотентен. Если репозиторий уже подготовлен, второй запуск ничего не
меняет.
